# SmartBI Data CLI

一个 SmartBI 数据取数辅助 CLI，用于在授权账号范围内，通过接口方式稳定、高效地完成报表数据拉取与本地处理衔接。

当前仓库仅保留项目说明，不包含可直接运行的内部包体、账号信息、BI 地址、报表路径、报表 ID、字段结构、业务配置、运行日志、截图或导出数据。

## 2.0 功能范围

SmartBI Data CLI 2.0 的定位很简单：把原本需要人工打开 BI、找报表、导出文件、检查文件、再交给本地脚本处理的流程，变成一套可检查、可复用、可追踪的本地命令。

它主要覆盖这些场景：

- 运行前检查：先确认本机环境、配置文件和必要依赖是否可用。
- 授权取数：在已有 SmartBI 权限范围内读取报表数据，不扩大账号权限。
- 报表导出：支持已配置报表的本地导出，并把结果交给后续分析或周报流程。
- 批量任务：把多个取数任务按清单执行，默认先走 dry-run，确认后才执行真实导出。
- BI 路线辅助：帮助判断一个业务问题应该找哪类 BI 报表或配置入口。
- 本地校验：检查导出的文件是否为空、字段是否符合预期、运行结果是否可追踪。
- 受控写回辅助：提供写回前的本地校验、差异比对和影子验证能力；真实写回必须单独确认。

它不做这些事：

- 不自动改变 SmartBI 生产数据。
- 不自动发布到飞书、GitHub、Obsidian 或其他外部系统。
- 不保存账号密码、会话、Cookie 或 Token。
- 不把具体业务报表、字段结构、报表 ID 或内部路径公开到本仓库。
- 不替代业务判断；CLI 只负责把数据拿稳、验清楚、留证据。

## 实现方式技术框架

用非技术语言理解，2.0 是分层做的：

1. 命令入口层：操作者只面对少量命令，比如检查环境、试跑任务、导出报表、查看运行结果。
2. 配置层：把“要取哪个报表、用什么时间范围、输出到哪里”放进配置文件，减少手工重复操作。
3. SmartBI 连接层：在授权账号范围内连接 SmartBI，读取报表或元数据；敏感账号信息只从本地环境读取。
4. 执行层：负责 dry-run、真实导出、批量执行、超时控制和失败记录。
5. 校验层：导出后检查文件是否有效、字段是否符合预期、运行过程是否留下可追踪结果。
6. 本地处理层：把导出的结果交给周报、数据清洗、分析脚本等下游流程。
7. 合规边界层：控制哪些内容可以公开，哪些只能留在内部包或受控交付渠道。

整体原则是：先本地检查，再授权执行；先 dry-run，再真实导出；先保留证据，再进入下游分析。
