# 01 第一条闭环 PRD

## 产品目标

让投放师不需要阅读 raw API 字段，就能在本地完成一次 Meta 投放检查、诊断、草稿和复盘。

## 用户故事

作为投放师，我希望系统读取真实 Meta 数据后，直接告诉我今天最需要处理的 Campaign / Ad Set / Ad、为什么需要处理、建议怎么改，并把建议保存为本地草稿，而不是让我手动翻 Ads Manager 或读底层字段。

## MVP 闭环

```text
账户总览
-> Campaign 列表
-> 异常诊断
-> 本地优化草稿
-> 安全确认 / 写操作阻断
-> 报表复盘
```

## 页面与动作

### 账户总览

- 展示账户名称、数据更新时间、近 7 天花费、线索、购买、LPV 等关键指标。
- 展示需要优先处理的对象数量。
- 明确标注数据来源是 Meta read-only 或本地快照。

### Campaign 列表

- 按处理优先级展示 Campaign。
- 展示投放状态、花费、结果、成本、趋势和主要异常。
- 用户可进入 Campaign 详情查看 Ad Set / Ad 层证据。

### 异常诊断

- 输出异常类型，例如花费异常、结果下滑、成本升高、REDACTED_CONVERSION_GAP、creative_asset疲劳、学习期风险。
- 每条诊断必须包含证据、影响范围、建议动作和置信度。
- 避免暴露 raw internal English fields 给普通用户。

### 本地优化草稿

- 支持生成本地草稿：预算建议、暂停建议、creative_asset复查建议、受众复查建议、复盘备注。
- 草稿只能保存在本地，不调用 Meta 写接口。
- 每份草稿记录来源诊断、创建时间、状态和操作人备注。

### 安全确认 / 写操作阻断

- 所有真实写操作入口必须显示 blocked。
- 禁止发布、暂停、预算、出价、creative_asset替换、复制后上线、删除等动作。
- blocked 事件写入本地审计日志。

### 报表复盘

- 输出一次闭环复盘：本次检查对象、发现问题、生成草稿、blocked 动作、待人工处理事项。
- 报表默认本地保存。

## 验收标准

- 使用真实 read-only 数据或本地快照时，页面能完成一条闭环。
- 在没有 Meta 凭证时，mock-to-live adapter 能跑通同样页面和测试。
- 任意真实写动作都不会调用外部 API，并有测试证明 blocked。
- 用户可见文案为简体中文。
